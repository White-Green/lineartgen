# OT を目的にしたノイズ生成・学習の再設計案

2026-09-08。これは調査と設計案であり、現行の Burn 再現設定を変更する実装ではない。
Gaussian noise 自体を固定する必要はない。必要なのは、学習時の輸送の始点分布を
Krita の推論時にもサンプリングできることである。

## 現行コードから分かること

Burn `src/train.rs` の `matched_diffusion_batch` は画像ごとの noise level を決め、
その値を使う corruption cost で候補を選ぶ。その後、
`sqrt(1-t) * x + sqrt(t) * z` をモデルに入れ、clean image を予測する。
現行 JAX 版もこの構成を引き継いでいる。

### coupling が時刻に依存する

割り当てを決めるコストは `||x - sqrt(1-t)*x - sqrt(t)*z||²` なので、
画像と候補を固定しても t を変えると一般に対応が変わる。
固定した端点 coupling を結んで経路を学習する標準の OT-CFM とは異なる。
時間依存 coupling に通常の補間の速度だけを当てはめても、OT-CFM の保証は引き継げない。
ここは元コードと CFM の定式化を突き合わせた考察。

例外として、全画素・全画像で共通の t、マスクなし、画像数と候補数が同数なら、
二乗ノルム項の総和が permutation に依存しないため、正の t で同じ最適対応になる。
Burn の画像ごとの t、マスク、多い候補からの選別ではこの条件を満たさない。

OT-CFM は端点の joint distribution とその上の補間経路を分けて定義する。
minibatch OT は母集団の大域的な OT の近似であり、割り当てを厳密に解いても
学習した生成過程全体が厳密な Wasserstein 最適輸送になるわけではない。
[Tong ほか: OT-CFM](https://arxiv.org/html/2302.00482v4)。

### 再帰各段のノイズ分布が学習・推論で異なる

Burn は各解像度で独立した Gaussian pool を生成して個別に割り当てる。
一方 `src/inference.rs` の `denoise_sample` は、最大解像度でノイズを加えた画像を
`tensor_pyramid` で縮小して各段へ渡す。JAX の training / runtime も同じ差を持つ。

未選別の iid Gaussian を 2×2 平均で縮小すると分散は 1/4、標準偏差は 1/2 になる。
512→16 の 5 回の縮小なら分散は 1/1024。学習で各段に生成する独立候補の分散は 1。
実際の選別後ノイズにはさらに選別による偏りが加わるため、この数値は候補分布の比較。
マスク境界では `pool(sqrt(t)*z)` と `sqrt(pool(t))*pool(z)` も一致しない。

第一の比較案は、端点を一度生成・割り当てし、ノイズを加えた画像全体から pyramid を作ること。
学習・推論の joint distribution を揃えられるが、各段の実効ノイズ強度も整理する。
独立ノイズを共有に変えるだけで性能が上がると確認したわけではない。

### 条件ごとの始点分布も必要

候補と画像を同数にすれば、全体では生成したノイズ集合を保てる。しかし、既知の線や
マスクなどの条件 c ごとのノイズ分布まで保つとは限らない。条件を無視した OT の
train / test mismatch と、条件距離を cost に加える C²OT が報告されている。
連続した条件に対する C²OT は近似。Krita のマスク・線へ適用した性能は未検証。
[Cheng & Schwing: The Curse of Conditions](https://arxiv.org/html/2503.10636v2)。

## 比較する設計

### 1. 時刻に依存しない端点 OT と線形経路

最初の比較基準として、画像と始点候補を同数生成し、端点の距離で pairing を決める。
その後に時刻を独立に引く。マスクなしでは通常の minibatch OT、マスクありでは
既知の内容を条件として扱い、独立 coupling と条件を考慮した coupling を比較する。
同じマスク形状だけで group 化しても、観測された線の内容まで同じ条件にはならない。

ノイズ側を t=1 として、線形経路を使うなら

```text
y_t = (1-t)*x + t*z
dy_t/dt = z-x
```

clean image の予測 head を維持してもよい。t>0 では
`v_theta = (y_t - x_hat)/t` と速度に換算できる。
この場合、無重みの velocity MSE は `||x_hat-x||²/t²` に相当し、
現在の `1/t` の loss をそのまま同じ FM objective と呼ぶことはできない。
t=0 の identity、端点の重み、時間の sampling を含めて設計する。
各再帰段の loss 重み・再帰を通る勾配・sqrt(batch) の LR は独立に維持できる。

推論 sampler も線形経路に合わせる。Krita の Strength は補間の時刻に対応付け直すため、
同じ数字で同じ破壊量になるとは限らない。旧 ONNX は経路の metadata で区別する。

### 2. ノイズ分布そのものをデータに適応させる

軽量な候補は `z = Q_phi(u), u ~ Uniform(0,1)` のように分位点関数で始点を生成する方法。
平均・分散だけでなく、白背景と線画の画素分布に合った非 Gaussian の周辺分布を持てる。
推論では同じ Q を使い、未知の正解画像を参照せず始点を生成する。
この方法を minibatch OT / FM と組み合わせた研究があり、MNIST では改善を報告している。
一方 CIFAR-10 では画素独立の prior による改善が小さく、空間相関の限界も報告されている。
[Chemseddine ほか: Adapting Noise to Data](https://arxiv.org/html/2510.12636v2)。

線画への適用は仮説。ランダム crop と回転を使う本実装では、固定座標ごとの Q より、
位置によらない Q、または解像度ごとの Q を最初に比較する方が自然と考える。
白画素の比率を近づけるだけでは線の連続性や配置は表現できない。
次の候補は、周波数帯ごとの強度を持つ Gaussian や条件付きの平均・共分散である。
目標の画素順にノイズを並べ替えるだけでは、推論時に生成可能な prior を定義したことにはならない。

### 3. 粗い線画を含む始点から高解像度へ輸送する

再帰構造を活かす発展案は、小さい解像度で生成した線画を拡大し、ノイズを混ぜて高解像度の
始点にすること。例は `z_high = (1-a)*upsample(coarse_generated) + a*epsilon`。
高解像度のモデルは粗い構造を初期状態から受け取り、主に細線や細部を補う。

低周波の画像分布を別の軽量モデルで生成し、そこから元画像へ flow matching する研究がある。
2026 年 6 月の preprint では few-step 生成の改善を報告している。
ただし、その noisy prior の OT 性は一般に自動保証されるものではなく、
再帰する同一 U-Net や Krita の入力条件への適用は本プロジェクトで別途検証が必要。
[Malnick ほか: Optimal Transport Flow Matching by Design](https://arxiv.org/html/2606.04092v1)。

現在の insert を足すだけの変更ではない。高解像度の時刻を引く前に coarse の生成手順を
定義する。学習で正解の縮小画像だけを使うと推論時の coarse 生成誤差にさらされないため、
生成した coarse を使う学習も必要。再帰段数・段ごとの loss 重みを維持しつつ、
実際の生成順序と勾配の経路を設計する。最小段には独立に生成可能な始点を残す。

## 推奨する順序と評価

まず 1 と再帰のノイズ整合性を比較基準にし、2 の軽量な学習 prior を追加する。
3 は今回の構造と相性がよさそうな発展案として、その後に試す。
これは実装の読み取りと他タスクの論文からの判断であり、線画の画質で選定済みではない。

再帰段数・各段の loss 重み・sqrt(batch) は固定し、以下を評価する。

- 固定した Krita 入力と seed、1 / 2 / 5 回の denoise における線の連続性・細線・線幅。
- 保護した線の変化、scribble への追従、生成結果の多様性。
- 全再帰段と prior 生成を含むモデル呼び出し回数・実時間。
- 生成経路の曲がり方と輸送コスト。ただし始点分布を変えた間のコストだけで画質を順位付けしない。
- ノイズの周辺分布・空間相関・解像度間の相関、条件ごとの train / test の差。

別候補の LOOM-CFM は batch 間で対応を保持・改善するが、本実装はランダム crop・回転・
マスクで学習サンプルが毎回変わるため、対応を保存する sample ID の設計が必要になる。
現時点では優先しない。[著者の解説](https://araachie.github.io/loom-cfm/)。
