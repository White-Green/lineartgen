# CR: 手掛かりを残した合成入力での16/32チャンネル比較

2026-10-13完了。32chは16chより訓練例・未見形状の両方で良かった。
この学習条件では幅を増やす効果がある。ただし、両方とも診断基準は未達であり、
16chの表現能力の限界、32chの必要性、実際の下描きでの品質は確定していない。
配布・採用モデルの変更は行っていない。

## 検証と実行コスト

3 CPUテストが15.74秒で合格。情報保持、データ分離、縮小後のノイズ、教師情報の混入なし、
各段lossの数式、モデル間の独立性、実更新後のfull-state復元を検証した。
GPUでは初期出力とlossを全6深さで一致確認し、最初の6実更新を別初期化から再現して
モデル・Adam・EMA・metricsが厳密一致。0/6/2000/6000のraw/EMA、計16 exportsが
対応するfull checkpointと一致した。各深さは1,000更新ずつ使用し、全6,000入力を記録。
コード・設定・データ・出力・画像のhash検証と完了処理も通った。

AMD GPUで初回6更新を除く平均更新時間は16ch 0.09209秒、32ch 0.12093秒（約1.31倍）。
入力生成と評価を含まない、交互実行時の実測である。推論速度の測定ではない。

## 次の判断

自己再帰CNNを捨てる根拠は増えていない。32chでも約6万パラメータと小さく、
この程度の幅の増加は有用な候補になった。まず同じデータ・lossで両サイズの学習を
延長し、16chが追いつくか、32chの薄線・白紙残差がどこまで下がるかを見るのがよい。
その後、ブラー・濃度を可変にし、元の手掛かりを残す合成下描きへ広げる。

今回の入力、256px、固定教師、初期化、one-passの学習法はCO/CP/CQと同時に変えている。
したがって旧実験からの改善を「情報を消す拡張を除いた効果」だけに帰属させない。
制御された比較は今回の16ch対32chである。同じ形状族の新しい乱数例を評価しただけで、
実際の下描き、未見の形状族、512px、複数時刻の推論、ONNX/Kritaの品質は未確認。
旧実験の凍結ファイル、封印した確認データ、独立確認seed20261005は変更・使用していない。
