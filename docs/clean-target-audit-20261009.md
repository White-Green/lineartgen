# 拡大済み教師画像とcrop分布の点検

追加学習でblur・細線の品質が落ちたため、**拡張前のclean教師**を点検した。学習seed2026100961の先頭64batch×4=256cropを、同じcache・正規化・回転反転で読み込み、geometry置換とsketch拡張は行わなかった。すべてtraining sourceで、検証用/封印用画像は使っていない。

| dataset scale | crop数 | 白紙crop率 | 広い中間濃度領域の平均面積率 |
| --- | ---: | ---: | ---: |
| images (0) | 28 | 0% | .031% |
| 2x (1) | 48 | 2.08% | .017% |
| 4x (2) | 76 | 9.21% | .082% |
| 8x (3) | 44 | 20.45% | .144% |
| 16x (4) | 44 | 34.09% | .558% |
| 32x (5) | 16 | 43.75% | 1.138% |

中間濃度はopacity.02–.98、その領域内で非中間濃度画素からの距離が2pxを超える画素を「広い領域」とした。最大距離は16xで18.1px、32xで26.1px。ただしcrop端に接する領域があり、これをそのまま線幅やhalo幅に換算しない。この小標本からデータ全体の割合を断定しない。

[倍率ごとの最大距離の教師crop](../runs/source-mixture-training-20261009/teacher-audit/worst-soft-native.png)を等倍で確認した。16x/32xの例には、太くぼけたグレーの線が**正解画像の側に既に存在する**。これは最悪例の選択であり典型例ではない。低倍率にも薄い細部はあるため、あらゆるグレーを不正な教師とみなさない。

元の[dataset/gen3.rb](/home/whitegreen/projects/lineartgen/dataset/gen3.rb:13)ではSwinIRモデルを使い、16xは2x画像→8倍、32xは4x画像→8倍と二段で拡大する。ベクター線を各解像度で再描画する処理ではない。記載の生成経路と実際に読み込んだ教師の状態を区別し、個別ファイルの生成ログを検証したとは主張しない。JAXのTIFF cache変換は元の画素を保持する処理である。

既存評価の`domain=real`は手描きrough/cleanペアを新規に使った意味ではなく、手続き的図形に対する既存の画像コーパスを指す。元のgen1/gen2スクリプトも生成モデルによる画像生成・線画化の経路を持つ。今回も自然下描きペアや外部データは追加していない。

これは、教師に忠実なlossと「輪郭周辺に広いグレーを作らない」という目標が一部で競合し得る具体的な証拠である。ただし、追加学習の悪化すべてを教師品質だけに帰属させることはできない。倍率によって線の太さ・構図・白紙率も変わる。

次の対照実験では、元解像度の教師だけを使うデータ方針を試す。再帰段数1–6の抽選は維持し、モデル・loss・crop選択seedは固定する。これは教師解像度とcrop内の構造を一緒に変える比較であり、「ぼけだけ」の単一原因の検証とは呼ばない。識別器比較の進行中の条件は変更しない。
