# EO: 8bit入力を混ぜても既知の途切れは改善しなかった

ENと同じ初期group6 raw18k、6,000更新、学習率・width拡張・merged geometry候補を使い、入力の50%だけ縮小前に8bitへ丸めた。追加学習群は1つ、対照は完了済みENを再利用した。frozen source `8643c04`。

9,516出力を作成し、事前固定34ページとscene1/7の追加等倍2ページを確認した。太い単線58と中間幅の改善、基本的な直線・曲線・分岐・交差・短い平行線、既知矩形の塗り、部分編集の保護は維持された。一方scene1の近接線の下側にはuint8/floatとも明瞭な薄い途切れが残る。floatはENの弱い連続部分より少なくとも目立つ途切れになっており、改善とは認められない。scene7の下側交差点での弱い縦線の余分な消失も変わらない。端部の汚れや学習幅外の断片も残る。

入力精度差による全画像RMSは平均0.00150515→0.00149850、最大0.00512918→0.00510968と僅かに下がった。しかし問題の局所形状は改善していない。この値を画質向上の根拠にしない。出力の閾値処理や画像平均は行っていない。

24,000例中12,058例を8bit化、6,000batch中5,584の入力が変わった。元/merged教師、許可フラグ、方向、maskはENと全更新で一致。非量子化batchの入力も一致。merged候補は許可1,244例中277例で選ばれた（EN278例）。6step再現、全状態復元、raw/EMA8exportは一致し、初期/対照の標準1,536・stress1,536予測ファイルと512px予測も完全一致した。有限値・範囲・保護領域の検証に合格。

CPU2testsと事前入力監査、継承した同一モデル/loss試験が合格。学習2区間は1,069.114秒と1,044.956秒、評価166.232秒、stress112.516秒、512px13.824秒、幅掃引5.255秒、すべて正常終了。末尾600更新の平均update時間は0.275228秒。

成果は `runs/precision-geometry-20261015/completion.json`、各visual-review、`diagnostics/{review-observations,extra-observations,integrity,decision}.json` に保存した。製品への採用と予約済み新規確認は行わない。次はENの幅拡張・候補を保ち、異なる濃さの複数の筆跡が同時に現れる合成入力を検証する。EOの入力精度だけの変更は解決策として採用しない。
