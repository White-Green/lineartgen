# FD: 小CNNは余分な短線を修復できるが、細い複合線はまだ不安定

幅6・16,402パラメータのCNNを既知の2形状で1,200更新すると、probe37は一本の滑らかな黒い曲線になり、左下の余分な短線が消えた。一方scene7は細い縦線や斜線が灰色と黒の斑な線になり、交差の途切れはきれいには修復しなかった。容量が全般的に足りないとも、現在のlossが十分だともまだ結論できない。

これは既知例へのfitting診断であり、汎化の成功ではない。Krita採用、export、未使用16例の評価はしていない。

- 固定コード `aa327e9`、run `runs/field-fit-20261015`、[事前計画](field-fit-plan-20261015.md)。EZ supported24kから新規optimizer、batch1、base LR2e-4×sqrt1→2e-5、全再帰深さ1〜6・全段loss・context dropoutを維持。各形状600更新。最終raw1200を結果とした。
- source/oracle/初期/400/800/1200を並べた原寸全体4枚と切り出し4枚を実際に確認。probe37の余分な線は400以降消えた。scene7は400/800/1200とも細線が斑になり、初期より汚くなった部分もある。部分編集の保護領域は維持。probe37部分編集は曲線全体が保護される対照であり修復成功には数えない。
- CPUテスト1件16.35秒、Ruff通過。CNNを通した勾配とFCのfield lossの合成勾配を照合。最初の12更新（両形状・全深さ）のmetrics/重み/optimizer/EMAは完全再現（最大差0）。全保存点の状態復元とraw/EMA計10exportが完全一致。初期予測は4条件ともEZと完全一致、全出力の保護領域も完全一致。
- 400更新ずつの実時間201.46/151.59/127.89秒、評価11.58秒、全終了コード0。2026-10-15 21:08:18〜21:16:46 UTC。直近600更新の平均0.16385秒。最終6深さのlossはscene7約0.069〜0.083、probe37約0.010〜0.013で、画像観察とも難しさの差がある。ただしlossの小ささでモデルを選ばない。

scene7のoracleは相対幅約0.45pxの線を要求する。この正確な太さ自体は「入力に沿う、きれいで連続した線画」に不可欠ではない。次は同じ入力・モデル・学習条件で、全pathを不透明2pxにそろえた教師を比較する。細い線を完全に模写するためだけの大型化を先に進めない。
