# N/Oの評価強度の範囲に関する訂正

Nの最終集計を点検して、固定した計画と集計コードの範囲に差を見つけた。計画では群別の保持条件を強度.1/.5としているが、コードは補助条件の0/.3/.7にも同じチェックを適用していた。画像生成、学習、指標値、閾値の誤りではなく、チェック対象の範囲が広すぎた。

元の`development/summary.json`と全指標を保存したまま、事前計画どおりのチェックだけを`development/planned-summary.json`へ分離する。強度を持たない主目的、黒い内部、白紙最大値の条件はすべて残す。余分な104チェックとその失敗も`auxiliary_checks`/`auxiliary_failures`として記録する。

Nの計画内チェックは402で、coverageが201中43、flat_coverageが201中48失敗。追加の104チェック中11失敗を含めたコードの元の集計は506中102失敗だった。**どちらの集計でも両候補は不合格で、Nの判断やOの起動条件は変わらない。** Oのqueueが参照した元のsummaryのハッシュも変更していない。

同じ評価コードを引き継いだOは、発見時点ですでに初期学習中だったが、1k/4kの評価前。この補助集計の問題はOにも適用し、最終判断では同じ事前宣言の.1/.5を使う。モデルの学習や凍結した数値コードを変更せず、外部の監査スクリプトで分離する。最終出力を見てから閾値を緩めたものではない。
