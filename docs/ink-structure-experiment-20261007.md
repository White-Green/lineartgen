# 線の保持と灰色抑制の継続実験

[前回の比較](lineart-loss-results-20261006.md)では、領域別lossでにじみが約17%減る一方、
細線の切断・ink不足が増えた。この副作用を抑えられる候補を探す。
実験が動いたことを完了条件にはせず、有望な候補は新しい合成条件と別学習seedで再確認する。
実際の下描きは使用せず、Krita入出力、縮小後のノイズ、再帰1〜6段、段間重み0、
sqrt(batch)による最大LRのスケーリングを維持する。

## 最初の比較

同じ最大UNetの100k EMAから6条件を開始する。2kで画像と数値を確認し、
対照と最大2候補を残して10kへ延長する。延長時はoptimizer・EMA・学習率の時計を含む
全状態を引き継ぐ。全条件でデータ・ノイズ・mask系列を共有する。

| 条件 | 変更 |
| --- | --- |
| control | 現行loss |
| no_contrast | contrast除去。補助項を比較する対照 |
| regions | 前回と同じ領域別loss、係数 .3133429447 |
| weak_regions | 領域別lossの係数を1/4（.0783357362）へ下げる |
| ink_guard | regions＋教師inkの不足を片側から罰する項、係数1.8161857349 |
| neighbor_guard | regions＋局所的なink不足の項 .5945581236＋局所的な背景過剰inkの項 .1779356456 |

単に前回の正則化を弱くする効果と、線の保持項を追加する効果を区別する。
neighbor_guardは二つの項を組み合わせた候補なので、成功した場合には個々の寄与の切り分けも必要。

実効batch16、最大LR4e-5、終端LR1e-6、warmup100、cosineの時計10k。
まず2kで止めるが、2kでLRが0になるscheduleにはしない。学習seedは20261007。
係数は初期モデルの出力に対する勾配をtraining splitの12batchで測って決めた。
ink側はbaseの中央値比20%・最大比75%、背景の追加項は5%・25%を上限とする。
parameter勾配の比率保証や、係数の最適性を意味しない。

## 新しいlossが扱うもの

inkを `a=(1-image)/2` とし、教師を `y` とする。教師ink>.02を線の支持領域とする。
`ink_keep` は `relu(y-a)^2` を教師ink量で重み付けし、画像ごとに線内で正規化する。
教師より暗くすることは報酬にせず、余分なinkは既存の画素・領域別lossで抑える。

neighbor項は、線内の不足と線外6px以内の背景への過剰inkを別々に計算し、
各誤差を3×3近傍の最大値で集計する。線側の最大値は線側、背景側は背景側からのみ拾う。
広く平均すると目立たなくなる弱い箇所や余分な橋渡しへの学習を増やす仮説。
背景項は隙間も含む近傍背景全体を扱い、独立した大域接続検査の代用ではない。

関連する[SCNPの原論文](https://arxiv.org/html/2603.18671v1)では、同じ教師クラス内で
最も悪い近隣logitに注目する方法を提案している。今回の項はその再現ではなく、
連続濃淡の教師に対する誤差を使った独自の比較。予測濃度そのものを最大・最小化しないため、
正しいアンチエイリアスや入り抜きもloss・勾配0になる。トポロジー保存の保証はない。

保護画素はlossの参照元と集計先の両方から除き、保護領域の誤りが編集側へ漏れないようにする。
単体テストでは、正しい連続濃淡教師・全保護の勾配0、欠けた芯を濃くする勾配、
白い隙間への侵入を薄くする勾配、空の領域での有限値を確認した。
GPUでは6条件×再帰1〜6段の36更新と、全状態の保存再開が成功した。

## 実験前に固定する採用条件

具体的な数値はrunの `acceptance.json`、確認用のseed・crop手順は `confirmation-plan.json` に固定する。
基準は同じ追加学習をしたcontrol。以下は実用上の点推定の許容値で、数学的保証や
ユーザーの主観的な満足を代弁するものではない。

- 強いstrokes劣化で、実線画由来・幾何の両方のhaloを10%以上減らす。
- clean、strokes/blur/toneのmild/strongを領域別に確認する。
  平均だけでなくstrength .1、部分編集、全体編集にも同じ保持基準を適用する。
- ink不足・消失断面率は+.5ポイントまで、切断・誤接続は+1ポイントまで。
  active F1低下は.005まで、線幅誤差増加は.10px、位置誤差増加は.05px、遠方背景ink増加は.0002まで。
- 固定画像で芯の消失、線幅・形状の崩れ、誤接続を確認する。rawは感度分析として併記する。
  数値判定だけでは採用しない。1/2/5回推論でも確認する。
- 別学習seedと、事前固定した新しい合成劣化・crop・noiseで再検証する。
  元画像/形状群単位の区間と、seedごとの結果を報告する。

2kの探索判定は緩く、いずれかの主群でhalo5%以上改善、ink不足+2ポイント以内、
切断・誤接続・消失+3ポイント以内を候補の条件とする。主群の平均halo改善率で順位付けし、
画像確認後に最大2候補を選ぶ。これは採用判定ではなく、悪化した条件へ長時間を使い続けることを防ぐもの。
候補がなければ原因・勾配・固定出力を確認し、係数や学習方法について次の仮説を立て直す。

既存developmentは1,562条件。反復用の画像は前回の31ケースに全体編集の幾何24ケースを加え、
計55ケースへ広げる。追加確認用には、既存final側の64元画像から新しいcropを使い、
幾何のvariant40〜43、劣化・noiseの新seedを予約する。
この64元画像自体は9月に評価済みで、未観察の元画像による最終testとは呼ばない。
確認結果を見て再調整した場合は、そのセットをdevelopmentに移し、別の確認条件を宣言する。

## 実行と記録

最初のrunは `runs/ink-structure-20261007-screen`。
`prepare_ink_structure_study.py` が条件・校正を作成し、`freeze_lineart_study.py` が
commit、コードarchive、全設定、検証記録のhashを保存する。
既存の学習・評価処理はprotocolの条件名を読めるように拡張した。従来の5条件が既定値。
旧runの入力・重み・結果は変更せず、当時のコードは各runのarchiveに保存されている。

`run_lineart_loss_study.py` と `watch_lineart_loss_analysis.py` が学習、EMA/raw評価、
全状態の監査、白紙・補足・反復診断を進める。2kの全状態と固定出力を確認してから次段階へ進む。
品質判定は `assess_ink_structure_study.py` の出力と実画像の両方で行う。
