# FF: 入力に沿う教師にすると小CNNでも交差を修復できた

入力の滑らかな位置ずれにteacherを沿わせると、同じ幅6・16,402パラメータのCNN、同じloss、同じ1,200更新で、scene7の下側交差の途切れと斑な濃淡が大きく改善した。斜線・縦線も滑らかで黒い線になり、意図された大きな隙間は残った。probe37の余分な短線の除去も維持した。

**既知2形状へのfitting診断であり、汎化の成功ではない。** この重みは採用せず、研究用の一般的な基準はEZ supported24kのまま。未使用16例、Krita、exportは触っていない。

- 固定コード `0ccd375`、run `runs/aligned-field-fit-20261015`、[事前計画](aligned-field-fit-plan-20261015.md)。FEとの変更はscene7のteacher位置だけ。不透明2pxの幅・接続・隙間は維持し、blurやopacityはteacherに入れない。source/guide/clean/noisy/strength/progressは全て完全一致、probe37のteacherも完全一致。
- source変位を逆写像してvector pathを移動した。実際のimage samplerで座標rampを変位した結果とのCPU照合で、写像の向き、pixel centerの0.5、margin32を検証。共有接点、変位0、各軸1.5px以内の変位も確認。学習前に原寸oracle2枚を見て、入力追従・連続性・滑らかさを確認した。
- 学習後は全体4枚・切り出し4枚、FEとの全域比較の全体2枚・切り出し2枚を実際に確認。事前確認込み原寸14枚。400以降、下側交差を黒い連続線として復元し、800/1200も維持。上側接点の小さな膨らみは残るが、FEのような広い斑や短い断片は大きく減った。部分編集でも改善し保護領域を保持。probe37部分は保護動作の対照。
- CPU2テスト1.01秒、Ruff通過。先頭12更新のmetrics/全optimizer/重み/EMAは完全再現（最大差0）、各checkpoint復元とraw/EMA10exportも完全一致。初期4条件の推論と保護領域も完全一致。FEとの形状・段数・dropout列は全1200更新一致、probe37のinput/teacher/mask digestも一致。
- GPU事前確認7.33秒、400更新ずつ137.37/128.38/129.69秒、評価14.87秒。全終了コード0。2026-10-15 21:36:44〜21:44:49 UTC。直近600更新平均0.16415秒。scene7最終6深さlossは約0.024〜0.027に下がったが、結論の根拠は連続性と実画像の改善。

この例では、モデルの大型化より「入力に沿う有効な線画まで、元位置からずれた誤りとして罰しない」teacherの作り方が有効だった。ただし完全な原因説明や一般的な十分性はまだ示していない。次は診断例を学習に含めず、既存512合成形状の広い学習にこの方針を移し、普通の線・太線・淡い線・部分編集への影響を確認する。初期EZから開始し、今回の2形状で学習した重みは引き継がない。

`completion.json` が入力照合、学習・復元記録、原寸レビューと判断を結び付ける。
