# DL: 曖昧な平行線の統合を許容する学習

DKでは薄い入力と黒ベタは改善したが、近接した平行線の灰色帯が残った。
現状の許容候補は位置と線幅を変えても線の本数を固定するため、下描きの重ね線を一本へ清書する出力を罰している可能性がある。
これを検証する。統合自体を常に正解とする実験ではない。

DK normalized raw18000からcontrol / mergeを各6,000更新する。初期重み・新規Adam/EMA・batch・augmentation・LRを一致させる。
16ch・3block・15,809パラメータ、全解像度source正規化、source-onlyを維持。
合成入力の実際の学習領域に合わせ、両configのimage_scaleを1.0と記録する。
train seed2026101341、評価2026101342、512形状、batch4、再帰段数1–6、全段重み.5**level、sqrt(batch)でpeak1e-4からcosine1e-5。
linear Charbonnier + .25経路断面 + .05範囲loss。全画像・全段を通じて一つの清書候補を選ぶ。
元候補のinkによる共通normalizerは両群で同じ。

変更は許容候補だけ。parallel種別の二経路で対応点の距離中央値が8px以下の場合に、二経路の平均位置を通る2pxの一本線を追加できる。
17断面で入力alphaを測り、peak>=.02かつ画像内の有効断面が8以上、その75%以上で中央部分の最小alphaが断面peakの.6以上の場合だけ許可する。
断面は二経路間距離の±1倍、中央部分は±.1倍。入力画像に残る明瞭な隙間や広く離れた線は統合対象にしない。
判定はaugmentation後の実入力に対し、正規化前に行う。形状情報は合成学習候補の生成にのみ使い、推論では不要。
9位置×3重複の27候補のうち各位置の重複1枠を一本線へ置換し、二本線の9候補はすべて残す。
学習前のデータ確認では512例中48例がparallel、27例が距離条件を満たし、27例でbase入力の統合が許可された。
この観察による閾値調整は行っていない。

CPUで幾何・入力支持判定、二本線候補の完全保持、一本線の不透明性、灰色混合より許容清書を低lossにすることを検証。
GPUで初期全6深さの出力一致、最初6更新の再実行(atol1e-7/rtol1e-5)、0/6/6000保存・完全状態復元・12 raw/EMA exportを確認する。
全batchの入力/normalizer/annotation hashは一致、候補hashは統合可能例を含む場合だけ異なることを要求する。

既存の標準4,608行・劣化4,608行と等倍16枚、512px複合8sceneの128出力・等倍6枚を確認する。
従来数値指標は線本数固定の候補との比較であり、正当な統合にも罰点を与えるため採否には使わない。
標準・劣化画像には元の二本線と条件付き一本線を並べ、灰色の側線、連続性、入力追従、明瞭な別線の消失、黒ベタのリングで判断する。
512px試験の意図的な隙間はdocs/scene512-interpretation-20261013.mdに従って区別する。
追加Gaussian2drawはsource-onlyのため独立な品質標本として数えない。出力の二値化・コントラスト補正は行わない。
合成のみ。Kritaと配布は変更せず、研究上の比較をもって製品採用とはしない。
