## 固定する条件

| 項目 | 条件 |
| --- | --- |
| 対象 | JAX のモデル・学習・評価。Krita 連携・配布への反映は今回の実験の対象外 |
| 入力 | 元入力画像の情報を保持。小さい段の予測は insert として渡す |
| ノイズ付加 | 画像と強度マップを各解像度へ縮小してから、各段で独立に生成 |
| 再帰 | `original_steps + dataset scale level`、標準 1〜6 段。重み共有と再帰を通る勾配を維持 |
| 各段 loss | `scale_loss_multiplier ** scale_index` と重み総和による正規化を維持。初期値 0 |
| 学習率 | base × sqrt(実効 batch)。base 1e-4、実効 16、peak 4e-4 |
| 基本条件 | crop 512、FP32、microbatch 4 × 蓄積 4、AdamW・clipping・EMA は現行設定 |
| OT | exact / SciPy、pool 256。小型化実験中はコスト・候補分布・solver を固定 |
| 基準 loss | 現行の denoise・identity・tone balance・Sobel・contrast |

内部 U-Net を 4 段から 3 段にすると最小入力サイズは 16 から 8 になる。
512 crop と現行の scale level 0〜5 では外側の再帰回数が同じ 1〜6 段に保たれることを
確認してから比較する。内部の深さと外側の再帰回数を混同しない。

## 0. 比較の基盤を作る

### データと乱数を固定する

- 元画像単位で train / development / final test に分け、全解像度の同じ元画像を同じ集合へ入れる。
  初期案は development 64 元画像、final test 64 元画像、残りを train。
- split を manifest に固定する。モデル初期化 seed を変えても分割・評価入力を変えない。
  現行 Trainer は train.seed が分割とデータ・ノイズにも使われるので、manifest と seed の
  分離を先に用意する。
- 最初の比較は初期化 seed 42。最終候補は 42 / 43 / 44 で確認する。
  初期比較ではデータ列・ノイズ列をモデル間で共通にし、最終確認では共通の分割の下で
  データ・ノイズ系列を変えた頑健性も確認する。
- final test はモデル・loss・係数の選定に使わず、選定後の確認に使う。

### 評価用の固定ケースを作る

| 集合 | 初期規模と用途 |
| --- | --- |
| 軽い development 評価 | 48 条件、各 dataset scale に 8 条件。学習中の傾向確認 |
| 詳細 development 評価 | 192 条件。線種・強度・mask を偏りなく選び、denoise 1 / 2 / 5 回で比較 |
| 幾何評価 | 256 条件の合成線画。接続・端点・曲率・線幅の正解が分かるケース |
| final test | 未使用の元画像から、詳細評価と同じ選び方・規模で作る。複数の固定ノイズ seed を使用 |

実画像には細線、太線、曲線、角、交差、近接線、ハッチング、入り抜き、
意図的な途切れを含める。合成評価には「つなぐべき欠落」と「つないではいけない隙間」を
分けて用意する。端点・交差・crop 境界を幅や曲率の評価から分離する。

強度は暫定的に 0 / 0.1 / 0.3 / 0.5 / 0.7 / 0.9 を使う。
主比較は 0.1〜0.7、0 は identity、0.9 は厳しい条件として別集計する。
この比重は利用頻度の実測ではない。実際の利用例があれば評価セットの固定前に反映する。
mask は全体、部分領域、線の保護、境界が線を横切る場合を含む。
全直積を回す代わりに、条件を均等に選んだ manifest を保存する。

### 評価指標を先に校正する

| 性質 | 評価 |
| --- | --- |
| 連続性 | 切断、誤接続、不要な閉ループ、端点・分岐の変化。中心線 precision / recall |
| 位置 | 正解中心線との距離と輪郭距離。中央値に加えて悪いケースも見る |
| 滑らかさ | 正解の接線・曲率との誤差。意図した角を平滑化した場合も失敗とする |
| 線幅 | 正解中心線の法線方向に測る被覆幅の誤差。交差・端点は別評価 |
| 細線 | 消失・二重化・アンチエイリアスの破壊 |
| 保護領域 | 入力からの変化量、mask 境界付近の変化。強度 0 の出力も確認 |
| 通常の再構成 | 画素誤差、既存の validation loss。幾何指標と併記 |
| 実用性 | 学習更新時間、読み込み待ち、推論時間、メモリ、総モデル呼び出し回数 |

正解へ意図的に「1 pixel の橋」「短い切断」「線幅増加」「角の丸め」を加え、
評価が期待どおり悪化するか検証する。実画像の skeleton / threshold に依存する指標は、
複数の閾値で傾向を確認する。合成の正確な幾何評価と固定拡大パネルで補完する。

合格条件の初期案は、重大な誤接続・意図した線の消失を基準より増やさず、
中心線 F1 の低下を 1 percentage point 以内、平均位置・幅の追加誤差を 0.1 pixel 以内とする。
これは利用者が指定した許容値ではなく、校正用の暫定値。上記の壊した出力が合格しないかを
確認し、モデル比較を始める前に固定する。全条件の平均だけで弱点を隠さない。
最終比較では元画像単位の対応付き集計・不確実性を示し、判定が不明なら結論を保留する。

### 読み込みの待ち時間を確認する

既存の [速度測定](training-speed.md) では images_32x の 16 crop の復号に約 2.3 秒かかった。
まず少数の元画像・全 scale で PNG と既存の tiled TIFF 前処理を比較する。
学習に渡る float32 crop の一致、変換時間、追加容量、Grain 経由の待ち時間を確認する。
採用する形式を全モデルで揃える。データ全体の変換はこの小規模確認後に判断する。

成果物: split / evaluation manifest、指標の校正例、固定比較パネル、I/O の採用条件。

## 0.5. 入れ子モデルで複数サイズの計算を共有できるか検証する

### 重みの共有と特徴計算の共有を分ける

幅を切り替えて同じ重みの一部を使う方法には、
[Universally Slimmable Networks](https://arxiv.org/abs/1903.05134) などの先行研究がある。
通常の全結合型の畳み込みでは、出力の先頭チャンネルも全入力チャンネルを参照する。
そのため、重みを共有するだけでは、最大幅の特徴の先頭部分を小型モデルの特徴として
再利用できない。幅ごとに forward が必要になる。

今回検討するのは、以下の一方向の依存関係を全層・全再帰段で保ち、
小型の特徴計算そのものを中型・大型でも共有する構造。
これは現行モデル向けの設計案であり、上記論文と同一の構造ではない。

| 次の層の特徴グループ | 参照できる前の層の特徴 |
| --- | --- |
| S: 小型の核 | S のみ |
| M: 中型で追加する部分 | S、M |
| L: 大型で追加する部分 | S、M、L |

畳み込みの出力を行、入力を列と見たブロック行列を下三角にする。
画像・ノイズ強度は全サイズで共通の外部入力としてよい。
ReLU、空間方向の pool、resize はチャンネルを混ぜないので維持できる。
現行モデルにチャンネル横断の正規化がないことも実装上は都合がよい。
各出力 head は、そのサイズまでの特徴だけを読む。

### 現行 U-Net で変更が必要な箇所

- encoder だけでなく、decoder の全畳み込みにも同じ制約を適用する。
  skip の結合後も、どの特徴が S / M / L に属するかを保つ。
- 現行 decoder は最後に全構成で共通の 2ch へ戻る。
  この共通 2ch に大型の特徴を混ぜてから出力を分岐すると小型が独立しない。
  最終 decoder にもサイズ別の追加特徴を残し、画像を作る head をサイズ別に設ける。
  中間でも追加特徴がなくなる層では、追加経路を残すか decoder を分岐する必要がある。
- 下位解像度の `insert` を S / M / L 別に保持する。
  S は S 自身の予測のみ、M の追加部分は S / M、L の追加部分は S / M / L の
  予測を参照できる。大型の予測を全サイズ共通の insert にしない。
  最小解像度の各 insert は現行どおりゼロで開始する。
- これにより大型は内部に小型の再帰状態も持つ構造になる。
  幅を広げただけの現行 U-Net とは異なる。大型を切り出す際にも、内部で必要な
  小型の head と再帰状態を含めてサイズ・計算量を数える。
- 推論を複数回繰り返す評価でも、各サイズの出力系列を維持する。
  入力がサイズごとに変わる時点では共有可能な計算が減るため、1 回の処理と分けて測る。

小型の核は M3 相当の約 6 千 parameters を出発点にできる。
追加する特徴数は decoder と head を含めて設計してから決める。
段階 1 の 12,393 / 21,079 などの独立モデルの parameter 数を、
そのまま入れ子の中型・大型の数として使わない。
初期検証では内部 pool 段数と conv / block は固定し、幅の追加だけを試す。

### 学習と比較の意味

同じ実効 batch の縮小画像・ノイズマップ・OT 割り当てを全サイズで共用する。
各サイズに従来どおりの教師画像に対する loss を置き、
初期案は `L = (L_S + L_M + L_L) / 3` とする。
各 `L_*` の内部の各段 loss、外側の再帰回数、再帰を通る勾配を維持する。
microbatch の勾配を蓄積し、全サイズ分をまとめて clipping・optimizer 更新・EMA 更新する。
同じ 16 枚から 3 出力を作っても実効 batch を 48 と数えず、学習率は base × sqrt(16)。
初期比較では大型の予測を教師にする蒸留を追加しない。

順伝播で S が大型の特徴・予測を参照しなくても、M / L の loss は共有された S の
重みを更新できる。小型だけで推論できる条件と、独立した学習条件は異なる。
まずこの共同学習を許し、S 自身の品質を監視する。干渉が見られた場合にだけ、
追加経路から共有部分への勾配を止める比較や loss の比率変更を別実験として行う。
共有重みでの順位は独立学習の順位と同じとは限らないため、
「このサイズでは足りない」という結論には独立学習の対照も必要。
参考: [CMU による weight sharing と順位の分析](https://blog.ml.cmu.edu/2020/07/17/in-defense-of-weight-sharing-for-nas/)。

### 長い学習の前に確認すること

1. 同じ入力・乱数・固定重みで、全サイズ同時計算と各サイズを切り出した計算を比較する。
   1〜6 段の全再帰・部分ノイズ・複数回の推論で、浮動小数点の許容誤差内の一致を確認する。
2. M / L 専用の重みと再帰用予測を変更しても S の出力が変わらないことを確認する。
   S の出力の M / L 専用パラメータに対する微分もゼロであることを確認する。
3. 切り出した S だけで保存・再読込・推論でき、大型用の配列や状態を要求しないことを確認する。
4. 同時計算、同じ入れ子モデルをサイズ別に再計算する場合、通常の独立モデルについて、
   初回 compile と定常更新時間、推論時間、メモリを比較する。
   ゼロマスク付き dense Conv とブロック別 Conv の速度は実測で選ぶ。
   ゼロにした結合の分まで自動的に高速化されるとは見なさない。
5. 短い品質比較は共有 S/M/L と独立 S で行う。現行 M0 は従来どおり品質の基準に使う。
   各サイズの品質曲線と、一定品質に達するまでの総 GPU 時間を記録する。

接続を一方向に制限するため、通常の同じ幅の dense モデルとは表現力が異なる。
また複数 head・再帰状態の費用があるので、「大型 1 本と全く同じ時間」とは約束しない。
成立条件と速度の確認後、品質を満たす最小の切り出しモデルを候補とし、必要に応じて
単独の追加学習を行う。独立学習の対照で改善するなら、容量不足と共有学習の干渉を分けて判断する。

## 1. まず現行モデルと約 1.2 万モデルを比較する

| ID | channels | conv / block | parameters | 役割 |
| --- | --- | ---: | ---: | --- |
| M0 | [4,10,20,40] | 3 | 126,765 | 現行構造の基準 |
| M1 | [4,8,16] | 2 | 12,393 | 最初の小型候補 |
| M2 | [4,8,16] | 3 | 21,079 | M1 の畳み込み深さが不足した場合の比較 |
| M3 | [4,6,8] | 2 | 5,933 | M1 が合格した場合の下限探索 |

独立学習の経路では、最初に走らせるのは M0 / M1 の 2 本、seed 42 のみ。
M1 は小型構造全体の仮説を試す比較であり、内部段数・幅・conv 数それぞれの寄与を
この 2 本だけから断定しない。原因が必要になった時点で追加対照を選ぶ。

学習率 schedule の終点は両方とも最初から 100,000 更新に固定し、
2,000 → 10,000 → 30,000 → 必要に応じて 100,000 更新まで同じ run を再開する。
`--stop-after` は追加更新数なので、2,000 から 10,000 へ進む場合は追加 8,000 とする。
途中で schedule の長さや設定を変えない。model / data / loss を変えた比較は新しい run にする。

- 2,000: 発散、全白への崩壊、再帰・mask の扱い、評価・保存・再開を確認する。
- 10,000: 改善傾向と失敗の種類を確認する。学習が遅いという理由だけで容量不足とはしない。
- 30,000: 品質と学習曲線を比較する。まだ改善していれば継続する。
- 100,000: 必要な候補の収束傾向を確認する。上限でも未収束なら最小サイズは未確定とする。

軽い評価は 1,000 更新ごと、詳細評価は上記の節目で行う。
同じ更新数・見た画像枚数での品質と、目標品質までの実時間を両方記録する。
通常の学習実行全体と、I/O・評価を除く更新時間を別々に測る。

分岐:

- M1 が合格 → M3 を同じ条件で試す。
- M1 の学習 loss 自体が十分下がらない → M2 を試す。必要なら受容野を保つ 4 段候補を追加する。
- M0 / M1 が同じ幾何の失敗をする → データ・loss の改善を優先する。
- 特定の mask / 強度でのみ悪化 → その学習例の不足と入力分布を先に調べる。
- M0 の品質が不十分 → M0 に近いだけの小型モデルを完成扱いせず、基準となる品質を改善する。

## 2. 小型モデルに必要な学習信号を一つずつ調べる

固定した小型構造と対照条件から開始する。以下を最初から全部組み合わせない。
各比較は原則 seed 42 の 10,000 更新までで見込みを確認し、改善中の候補は継続する。
採用した変更だけを次の対照条件へ加える。

| 優先 | ID | 一度に変えるもの | 確認したいこと |
| --- | --- | --- | --- |
| 1 | D1 | 実画像 80% + 合成線画 20% | 接続・幅・曲率の例を増やすだけで改善するか |
| 2 | L1 | 対照 + 境界 / 距離場の補助 loss | 位置・幅・細線が改善し、線が痩せないか |
| 2 | L2 | 同じ対照 + soft-clDice | 切断が減り、誤接続や意図した途切れの破壊が増えないか |
| 3 | N1 | 利用条件に合わせた強度の sampling | 使用域の品質が上がり、強いノイズへの性能がどれだけ変わるか |
| 3 | N2 | mask / 線の境界を含む例の sampling | 保護した線と部分処理の境界が改善するか |

D1 の 20% は初期値。合成には曲線、角、交差、分岐、近接線、幅変化、入り抜き、
意図した隙間を含め、サブピクセル位置と角度を変えて描画する。白背景の例も維持する。
入力は対照と同じ縮小・Gaussian・OT 処理で作り、最初の比較では摂動の種類まで同時に変えない。
合成評価とは seed と形状の組合せを分離する。実画像を見た累積枚数も記録する。

L1 / L2 は主たる画素 loss と identity を残す。係数は小規模 pilot で校正し、
同じ比較群内で固定する。補助 loss は既存の各段 loss の内部に追加し、段ごとの重みは変えない。
L1 / L2 がそれぞれ有効だった場合にだけ併用を試す。
参考: [Boundary loss](https://proceedings.mlr.press/v102/kervadec19a.html)、
[soft-clDice](https://arxiv.org/abs/2003.07311)。線画での効果や接続の保証は未確認。

N1 の sampling 比率は評価ケースを固定した後に定める。正解を持つ評価ケースだけを見て
都合よく使用域を狭めない。強度 0 と部分 mask は維持する。
入力の揺れ・幅ムラを直接壊す学習は、実運用の補正対象に合うかを確認して別の比較にする。

最初の比較で見込みがない変更は持ち越さず、残る誤りに対応する比較を選ぶ。
最終的に採用したデータ・loss は M0 にも適用し、改善前の弱い基準だけに勝っていないか確認する。

## 3. 残る失敗に応じて接続構造を調べる

学習方法で解決しない場合に、同じ小型モデル・同じ学習条件で以下を独立に比較する。

| ID | 変更 | 主な判断対象 |
| --- | --- | --- |
| A1 | 入力画像からの残差を予測する出力 | identity、保護領域、低ノイズ時の不要な変形 |
| A2 | pool 前の高解像度特徴を使う skip | 細線、角、線幅、サブピクセル位置 |
| A3 | 内部の受容野を広げる候補 | 外側の再帰が 1 段のケース、長い接続の判断 |

A1 / A2 は片方ずつ比べ、有効なら併用を確認する。
変更後は parameter 数・MAC・実時間を再計測する。チャンネル数が同じでもモデルサイズが
同じとは限らない。下位段から渡す情報が 1ch の予測画像だけである点も、失敗原因の診断に含める。

## 4. 最小サイズを確定する

採用した学習条件で M1 → M3 と縮め、境界付近の候補と M0 を seed 42 / 43 / 44 で比較する。
構造変更を採用した場合は、実測 parameter 数で候補を記録し直す。
開発用評価で選定後、final test と名前を隠した固定拡大パネルで確認する。
最終モデルは、平均点だけでなく各線種・各再帰段数・部分 mask の合格条件を満たすものから選ぶ。

成果物は、採用 config・checkpoint・再現可能な評価入力、全候補の品質と時間の表、
弱い条件の例、同じ条件での再開手順。結果が不確かなら「最小」と断定せず次の追加比較を明記する。

## 実験数と時間の扱い

- まず 0.5 の入れ子構造の成立条件と短い比較を確認する。
  独立学習の経路では最初は M0 / M1 の 2 本とし、M2 / M3 は結果に応じて追加する。
- 学習方法・接続構造は失敗に対応するものを優先し、全組合せを総当たりしない。
- 小型候補の実速度は初回 pilot で測り、以後の所要時間を更新する。
- 過去の M0 の実測では、10,000 更新の計算部分だけで約 2.4〜3.2 時間、
  100,000 更新で約 24〜32 時間に相当する。これは 1 / 6 段の固定条件からの外挿であり、
  通常の scale 混在、I/O、詳細評価を含む所要時間ではない。
- 最終の複数 seed は比較候補を絞ってから行う。短い pilot の順位だけで採用を決めない。

初期実験から分けておくもの: ノイズ生成器・OT コストの変更、depthwise 化、量子化、
新しい再帰状態の導入、大規模な蒸留。小型化と教師・loss の効果が見えてから優先順位を決める。
