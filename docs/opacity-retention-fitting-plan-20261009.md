# Tempered tone weights with linear opacity retention

Declared before implementing or training these candidates. The completed tone-weight study found that square-root weights reduce blur/.1 halos by 47.486% / 49.433% on train/probe, with no F1 safeguard failures, but all 24 strata lose too much ink opacity. Unit weights fade thin lines further. All twelve fixed native sheets were inspected. The separate unit-weight conditional-path study is running and keeps its own frozen decision rules.

Test whether a linear, one-sided deficit term can preserve target opacity while retaining the tempered pixel loss's stronger relative background penalty. For teacher opacity y=clip((1-clean)/2) and prediction opacity p=clip((1-prediction)/2), set core = editable AND y>.02. The new loss is the batch mean of `sum(core * relu(y-p)) / max(sum(core*y), 1e-6)` per image. Empty cores contribute zero. Teacher/support/denominator are stopped-gradient. ReLU has zero derivative at exact teacher agreement. Correct antialiasing and over-dark teacher pixels receive no extra force. Background and protected pixels receive no force from this term. Pixel/edge terms still penalize over-darkening and unwanted marks.

This matches the evaluation ink-deficit fraction on images with active ink (the training editable mask uses the existing min-noise threshold). Unlike the old squared, teacher-opacity-weighted ink_keep, it does not weaken its derivative as a small deficit approaches zero, and does not downweight thin gray teacher pixels a second time. It does not guarantee continuity, separation, or correct conditional sampling; extra darkening may reproduce the halo failure. Those are reasons for the fixed visual and metric safeguards.

Use the same 130,605-parameter width16 source-guided model, ordinary rough path, no progress conditioning, and original 100k EMA with zero added outputs. Reuse exact 57/57 local train/probe pairs, seed2026100801, indexed batch4, independent Gaussian draws, masks, depth1–6, stage weighting0, base LR1e-4 scaled by sqrt(4), warmup50, cosine1,200 updates ending1e-5, EMA.999, identity.1/edge.1/contrast.01/noise_floor.05. Both arms use tone_balance_power=.5:

- `warm_opacity_010`: opacity_deficit_weight=.1.
- `warm_opacity_030`: opacity_deficit_weight=.3.

These are predeclared modest/strong auxiliary coefficients, not estimates of an optimum. Both start from the original initialization, not the square-root fitted endpoint. All other auxiliary terms retain zero. The default new coefficient is zero so historical behavior and inference architecture are unchanged.
