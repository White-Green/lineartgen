# DN: 段情報と清書ink正規化の比較結果

3群それぞれ18,000更新を完了。標準8枚・劣化8枚・512px6枚・全parallel/wide6枚・wide劣化5枚、計33枚を等倍で実際に確認した。
全群15,809パラメータ、RF87。対照は同条件で完了したDM thinwide raw18000を再利用した。
**清書inkでの正規化は太い入力から線を残す方向に効いたが、どの群も製品採用条件を満たさない。**

## 出力からわかったこと

| 条件 | 観察 |
|---|---|
| level: 段情報だけ | 太い入力の消失がむしろ増え、灰色の輪郭だけ残る例が多い。近接線・交点も解決しない |
| balanced: 清書inkで正規化 | wideの中央の線が明確に濃くなり、一部の斜線は連続して復元。ただし短い線の欠落、端の残骸、縦線の灰色側線が残る |
| both: 両方 | balancedと同様の太線復元効果。一部の近接線は濃くなるが、安定した追加効果は確認できない |

wideのold62/new63や劣化63ではbalanced/bothが明確に改善した。一方、new62は短い不規則な残骸、
old63/new59は二重の縦の灰色帯、部分処理58/62は処理範囲内の端が消えたまま。
これは単なるMSEの差ではなく、線の存在・連続性・端点を保てていない失敗である。

DMで副線が減っていたnew_probe36/38と512px scene5では、今回の群で灰色の副線が再び見える。
scene2の灰色の不規則な弧、標準crossing30の交点の切れ、sharp6の二重の灰色輪郭も残る。
blackの内部は黒いが、角の白い傷と内側の細い白枠があり、level/bothでは枠が目立つ。
balancedは連続した枠が弱い一方、角の傷は残る。薄い線を保持するDK由来の改善は維持している。

scene1/7の大きな意図的gapと、部分処理の保護領域に残した灰色は失敗として数えていない。
描画された2px教師は許容候補の一つであり、正確な位置一致や二本線の維持そのものを必須にしていない。
問題は不透明な連続線にならず、灰色の帯や不規則な断片が残ることである。

## 検証記録

- 数値コードcommit: `8bf16a8`。CPU40 tests passed、Ruff passed。
- 全6深さの初期関数・初期パラメータ一致。対照6更新再現と新規群6更新再現は事前許容値atol1e-7/rtol1e-5以内。新規群の最大差1.49e-8。
- 0/6/6000/18000の完全状態と24 raw/EMA exportを復元照合。
- 全18,000バッチで入力・候補・幾何は群間一致。levelの全入力hashはDM thinwideと一致。wide出現6,758/72,000件。
- 標準6,144＋劣化6,144行、512px追加192出力。再利用対照3,072比較で完全一致。
- Gaussian draw変更: 標準3,072組・劣化3,072組・512px96組で完全一致。source-only構成の確認であり、OTや生成多様性の成果ではない。
- 512px保護領域は完全一致。uint8/float出力RMSの平均はlevel .001286、balanced .001256、both .001239、最大は各.003920/.004000/.003913。
- 最後600更新の平均update時間はlevel .1026秒、balanced .1051秒、both .1026秒。入力準備・hash計算を含まない。

機械可読記録は `runs/scale-style-balance-20261014/completion.json` と `diagnostics/*/completion.json`。

## 判断と次の切り分け

今回の結果は、太い元線画のinkを分母にして清書の消失コストを小さくしていた問題を支持する。
ただし清書inkに変えるだけでは不十分で、段情報だけで解消するという仮説も支持されなかった。
単一seed・繰り返し使った評価形状による診断であり、独立した汎化確認ではない。

学習200更新時点で別seedの512px合成16例を予約したが、事前の採用条件を通過した群がないため、
その確認用推論は実施していない。別seedへ替えてよい例を探すこともしない。
次は既知の少数形状を用い、同容量モデルが固定した入力に十分な線を描けるかを調べる。
これは学習可能性の診断であり、少数例への適合を汎化性能や製品候補と扱わない。
Krita・配布・後処理thresholdは変更していない。
