# FE: 均一幅の教師だけでは複合線の問題は解けなかった

入力は全て同じに保ち、scene7の教師だけを不透明2pxの均一幅にしたが、1,200更新後も交差付近の途切れ、斑な濃淡、斜線や縦線の細かい二重の痕跡が残った。相対幅0.45pxを厳密に模写する要求だけが原因ではない。probe37の短線除去はFDと同様に成功した。

これは既知例のfitting診断であり汎化の改善ではない。Krita採用・export・未使用16例の評価は行っていない。

- 固定コード `46804f3`、run `runs/uniform-field-fit-20261015`、[事前計画](uniform-field-fit-plan-20261015.md)。初期EZ supported24k、幅6・16,402パラメータ、batch1、LR2e-4×sqrt1→2e-5、新規optimizer、深さ1〜6・全段loss・context dropoutをFDと同一にした。
- source、guide、clean、noisy、strength、progressは準備のたびにFDと完全一致を検証。probe37はteacherも完全一致。scene7はteacherの幅だけを変更し、位置・隙間・接続を保持。
- 原寸全体4枚・切り出し4枚、FDとの全域比較の全体2枚・切り出し2枚、計12枚を実際に確認。均一幅oracle自体はきれいな連続線画だが、学習結果は400/800/1200ともscene7で乱れが残る。初期より汚くなった部分もあり採用しない。probe37部分は全形状が保護された対照。
- CPU1テスト1.16秒、Ruff通過。先頭12更新のmetrics/重み/optimizer/EMAは完全再現（最大差0）、全checkpoint復元と10 raw/EMA exportは完全一致。初期4条件と保護領域も完全一致。FDとの形状・段数・dropout列は全1200更新一致し、probe37のinput/teacher/mask digestも一致。
- 400更新ずつ137.52/128.79/128.88秒、評価15.02秒。全終了コード0、2026-10-15 21:22:39〜21:29:46 UTC。直近600更新平均0.16392秒。scene7の最終6深さlossは約0.069〜0.084でFDと大差なく、画像も明確には改善しなかった。lossの小ささによる採用はしていない。

次に調べるのは教師の位置指定である。現在のrough入力は滑らかな変位を受けるが、teacherは変位前の形状に固定される。入力に沿った近傍の滑らかな曲線も有効な線画なので、入力と同じ変位に沿うteacherを比較する。変位を戻す逆問題を解けないことと、きれいな線画を出せないことを区別するための診断であり、原因はまだ確定していない。
