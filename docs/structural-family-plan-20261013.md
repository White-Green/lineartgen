# DJ: 端点・接合点の局所領域loss

DIの通常畳み込みでも拡張畳み込みでも、交点の途切れと端点の余分な形が残った。
既存の経路断面は弧長5–95%を測り、真の端点/共通接合点を中心にしていない。
全画像lossには接合部も含まれるが、局所的な欠陥が長い線全体の平均に埋もれる可能性を調べる。

DI plain raw18000からcontrol/structureを各6,000更新。16ch・3残差block・15,809パラメータのまま。
同じ初期パラメータ・全6深さ初期出力・fresh Adam/EMA。train seed2026101337、eval2026101338。
同じ512合成形状、2pxの複数許容清書、25%標準/75%透明度.2–.8・σ.6–2.4・揺れ0–1.5の入力。
再帰1–6、各段.5**level、batch4、sqrt(batch)peak LR1e-4→cosine1e-5を維持。

各pathの真の両端を中心に17x17画素の領域を置く。複数pathの共通始点が交点/接合点になる。
領域はunionして重複を数えない。全候補に同一の領域を使い、許容する±2pxの平行移動を含める。
領域maskもbox縮小し、各段のclean被覆率を使う。coarseを二値にする規則は加えない。
保護画素は除外。空白/黒ベタにはpath端点がないため追加lossは0。

controlは既存pixel + .25 path + .05 range。
structureは、上記領域でのlinear Charbonnierを領域内の元候補平均線量で割ったcostを係数2で加える。
領域はまとめて一つのcostとし、端点ごとの独立した候補選択はしない。
pixel/path/局所領域と全段を合算した後、画像全体で一つのclean候補を選ぶ。
係数は画質を見る前に2と固定し、短い局所領域に平均誤差の中で明示的な重みを与える。
これは清書の幾何学的な保証ではなく、学習の重み付けの比較。SDF/clDiceや新しい段符号は実装しない。

CPUで端点/接合点の領域、重複排除、境界外、全段の重み、許容候補/灰色平均/継ぎ接ぎの区別、
欠損・飽和への実勾配、保護、coefficient0と既存loss/勾配の厳密一致、実更新、保存復元と次更新を検証する。
GPU最初6更新は事前固定atol1e-7/rtol1e-5で再実行。6/6000全状態復元、12raw/EMA exportは厳密一致。
6,000回の入力/候補/annotation hash一致を確認。保存0/6/6000、画質の主評価はraw6000のみ。

標準4split×64×3mask×2draw×3モデル、劣化6×64×2mask×2draw×3モデルの合計9,216行。
事前指定の標準8枚・劣化8枚を等倍で見る。追加512px/float-uint8/全体-部分の128出力と6枚も
scriptと入力を事前束縛して確認する。唯一の教師とのMSEや平均値だけで採用しない。
改善の判定は交点の連続性・端点の形・灰色の側線・滑らかさと保護を中心に行う。
黒ベタの課題は今回の追加lossが直接扱わないため、その改善を事前に期待しない。

合成のみ。source-only one-passであり追加Gaussianの多様性/OT保存は主張しない。
Krita/配布は変更せず、独立確認seed・封印データは探索後に別途必要。
