# 一様な黒い面への応答 — 開発用診断

L/Mの黒ベタ劣化が特定の画像の模様だけによるものかを調べるため、512pxの一様な入力で確認した。Nの最終出力を見る前に、入力alpha0/.25/.5/.75/1、強度.1/.5、全域／部分編集の20条件を固定した。alpha0は白紙、他は黒ベタの透明度を落とした合成入力。編集対象かつ画像端・保護境界から32px超の内部を集計する。追加の採用条件や未見確認ではない。

CPU JAXで既存のE/L/Mを評価した60条件は完了。強度.5・全域の内部平均alphaは次のとおり。黒ベタ教師の期待alphaは1。

| 入力alpha | E初期値 | L元解像度教師 | M均一loss |
|---|---:|---:|---:|
| 0（白紙） | 0 | 0 | 0 |
| .25 | 1 | .401550 | .388959 |
| .50 | 1 | .412461 | .448189 |
| .75 | 1 | .507646 | .539632 |
| 1.00 | 1 | .596461 | .706869 |

**透明度を落としていない黒ベタまでL/Mはグレーにする。** したがって、部分編集717/727だけの例外ではない。白紙内部は全モデルで白く、観測した白紙の余分な濃度は端に集中する。これは同じ黒ベタを保てたEからの追加学習で生じた変化だが、この診断だけでデータ不足・最適化・表現のどれが原因かは決めない。

全条件で有限出力、保護画素の完全一致を確認した。CPU数値であり、GPUとのビット一致を主張しない。N完了後に同じ条件で再評価し、黒い面の追加がこの応答を直したかを確認する。
