# 学習済み候補の1回復元・実BGRA検証

元画像特徴の候補用に、指定強度を各再帰解像度で1回だけ評価する明示的な
`sampling_mode="one_pass"` を実装した。従来のdiffusionモードは既定のまま。
新モードは元画像特徴・元画像を基準にした残差出力に限定する。

このモードではAPI上のdenoise_steps1–20は受理するが、値を変えても結果は変わらない。
Gaussian seedも使われない。途中の生成状態を使わないモデルのため、従来の反復を
適用して実質強度がstrength/Nになる挙動を避けるための、意図的な変更である。
反復的に改善するモデルを実装した意味ではない。BGRA引数・戻り値は維持。

ONNX metadata形式2を導入し、古いruntimeが誤った反復で読み込むことを防ぐ。
対応runtimeは形式1と2を読み込める。UIと配布中モデルは変更しておらず、新形式には
この更新を含むruntimeが必要。まだ配布用のパッケージには切り替えていない。

既存source-signal raw4kの130,605パラメータを完全一致で複製し、設定だけ変更した。
12個の開発画像と全域/部分白紙、強度.1/.5、要求回数1/5/20の84条件を、実際の
LineartModel.inferへBGRAで入力した。追加seed変更28条件も確認した。

| 確認項目 | 結果 |
| --- | --- |
| JAXの既存1回推論との比較 | 完全一致 |
| CPU ONNXとJAXの最大連続値差 | 4.232e-6 |
| BGRAの最大差 | 1階調 |
| 要求回数1/5/20・seed変更 | byte単位で同一 |
| 保護画素の連続値 | 入力と完全一致 |
| 保存し直したパラメータ | 元checkpointと完全一致 |
| 新規・回帰テスト | 26件pass |

BGRA量子化で入力に最大.004314の差が生じるため、JAX比較にも実APIで復号した入力を
用いた。この入力差をモデル差と混同していない。数値コードa6b776aと入力・checkpointを
推論前に固定し、最終6枚を実際に確認した。
